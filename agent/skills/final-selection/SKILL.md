# Skill: 终选（final-selection）

> 触发场景：候选池已经生成（`runs/agent/<日期>/packet.md` 存在），
> 需要有人决定这一次到底给用户看哪几条。
>
> 这个技能**只**负责终选。抓取、打分、调参各有各的技能与工具。

## 前置条件

| 需要 | 检查方式 |
|---|---|
| 打分行 | `calibration/scores-*.jsonl` 存在 |
| 抓取产物 | `runs/crawl-*/items.json` 存在（提供正文摘要） |
| 需求快照 | `demand/demand-*.json` 存在且 `state.status == OK` |
| 角色说明 | 已读 `agent/AGENT.md` |

缺任何一条就停下来补，不要凭记忆做终选。

## 步骤

### 1. 生成终选包

```
python tools/agent_select.py --build \
  --scores calibration/scores-crawl-ai.jsonl \
  --items runs/crawl-20261018T080741Z/items.json \
  --demand demand/demand-2026-01-01.json \
  --out runs/agent/<日期>
```

产出 `packet.md`（读它）、`decision.json`（填它）、`candidates.json`（核对用）。

### 2. 先读完需求，再看候选

把 packet 头部的四条方向抄到草稿上，**然后再翻候选**。
反过来做（先看候选、再想需求合不合）会被内容牵着走，这是终选最常见的失败方式。

### 3. 分桶

对每条候选只做一个动作，桶之间不重叠：

| 桶 | 判据 | 归属 |
|---|---|---|
| 先排掉 | 招聘/采购/广告/报名；只有新闻流水 | `excludes` |
| 当前任务 | 能直接推进手上这件事 | `picks: core` |
| 主目标 | 能改进架构/契约/评测/工具链 | `picks: core` |
| 第二方向 | 能给叙事/构图/光影/节奏提供可用的东西 | `picks: core` |
| 探索 | 同一抽象概念在别处的化身 | `picks: exploration` |
| 都不是 | 相关但不有用 | `excludes` |

### 4. 按容量截断

核心位先放「当前任务 + 主目标」，其次「第二方向」；探索位最多 2 条。
**宁可少于 7 条**：空位不代表失败，凑数才是。

### 5. 写理由（这一步最容易糊弄）

每条理由必须同时包含两个成分：

1. **它是什么**（一句话概述，证明你真的读了摘要）；
2. **它帮到我什么**（指向具体动作、具体设计、具体判断）。

排除的理由要写**「哪一维误判了」**，因为它会回灌给调参层：

**禁止用「没讲方法」作为排除理由——任何领域都一样，不只是艺术。**

政策 §2.1 的可检验性是「能够对应证据、实验、原始材料或**可观察结果**」。
一个作品、一个原型、一次演示、一个上了线的模型，都是可观察结果。
政策 §2.3 第 5 条要降权的是「**只**宣传热度或宏大愿景、**却没有实际能力**」的内容——
限定词是「没有实际能力」，不是「没有讲方法」。

| 想排除时先自问 | 如果是 | 那就 |
|---|---|---|
| 它只有热度，拿不出实际能力？ | 是 | 可以排除（§2.3-5） |
| 它有实际形态，只是没解释方法？ | 是 | **不能**据此排除（§2.1 可观察结果） |
| 它只有商业动作（公关/活动复盘/水文）？ | 是 | 可以排除（§2.3-1/4/6） |
| 它只有技术参数清单，没有取舍判断？ | 是 | 可以排除（不属于作品，属于说明书） |
| 只是「解释力不够」「没论证成立条件」？ | 是 | **不能**据此排除（§2.1 是加权项，不是准入门槛） |
| 它是产品/设备评测（型号、参数、发布）？ | 是 | 降权——标注人明确说过「产品不要推，需要时会自己找」 |
| 它通篇正确但「谁都知道」？ | 是 | 认知增量不足（§2.1），可排除 |
| 它只是「另一个领域有意思的事」？ | 是 | 不算跨领域；跨领域要同构结构 |

| 排除原因 | 写法 |
|---|---|
| 方向其实不对 | 「建筑作品展示，secondary 给到 0.64 是误判」 |
| 相关但没用 | 「关于 AI 的新闻汇总，可知道但不可用」 |
| 形态问题 | 「设备评测，本质是产品页」 |

### 6. 落盘并校验

```
python tools/agent_select.py --apply \
  --out runs/agent/<日期> \
  --scores calibration/scores-crawl-ai.jsonl \
  --items runs/crawl-20261018T080741Z/items.json
```

校验不过会逐条报错并拒绝写入。**不要绕过校验去手改 selection.json。**

### 7. 把取舍回灌给调参层

```
python tools/learn.py --user me --scores runs/live-<日期>/scores.jsonl \
  --from-overrides runs/agent/<日期>/selection.json --apply
```

（`--from-overrides` 直接读 selection.json 里的 `override_events`；少于 3 条不一致只进 pending，不提交。
提交出的新版本会被下一次 `--build` 读走——权重和阈值都变，不需要手工改参数。）

## 检查清单

- [ ] 四条方向读过并抄下来了
- [ ] 每条候选都被分到了某个桶（没有「跳过没看」）
- [ ] 每个 pick / exclude 都有非空理由
- [ ] 理由里没有出现「很好」「值得一读」这类评价词
- [ ] 核心 ≤5、探索 ≤2
- [ ] 探索位里的内容，确实是「同一概念的别处化身」而不是「另一个领域」
- [ ] 排除视觉/设计/影像类条目前，单独问一句：「这个作品本身对我有用吗？」
- [ ] 没有一条排除理由写的是「只是展示」「没讲方法」「没说清用途」
- [ ] 没有一条排除理由只靠 §2.1（解释力/可迁移性…）——那些是加权项，不是门槛
- [ ] 每条排除都能指到政策某一款（§2.3-1/4/5/6），指不到就不该排
- [ ] `--apply` 通过校验

## 反模式

| 不要 | 因为 |
|---|---|
| 用分数排序直接取前 5 | 那就等于没有 Agent 这一层 |
| 为了「覆盖多个领域」而选 | 用户要的不是覆盖面，是能用的东西 |
| 把「没讲方法」当排除理由 | 作品/原型/模型本身就是可观察结果（§2.1）；漏掉的往往是最好的那批 |
| 凭自己的口味加规则 | 判断必须回到政策条文，不能是 Agent 自己的偏好 |
| 把没把握的条目偷偷跳过 | 不表态 = 没有反馈，系统学不到任何东西 |
| 改阈值让自己好选 | 阈值属于调参层，改了就分不清是谁的功劳 |

## 一次真实样例（2026-10-18，11 条候选）

| 决定 | 条目 | 理由要点 |
|---|---|---|
| core | 腾讯 AI 智能体在高德折腾 11 天 | agent 借公共浏览器执行代码的具体路径 |
| core | 佩列西安「距离蒙太奇」 | 一种把镜头当积木的叙事手法，可用于片段组织 |
| core | 特斯拉 Roadster2 演示 | 技术叙事的样本（用户已在前一轮确认过） |
| exploration | 梓美术馆「散点叙事」 | 中国山水长卷的散点透视 → 建筑动线，正是「叙事在别处」 |
| exploration | 特斯拉发布会「是何意味」 | 一场发布会如何被设计成可传播的叙事 |
| 排除 | Huggingface 27B 榜单 | 27B 部署不了；需要时主动搜，属于「知道一下」 |
| 排除 | 临港产业园改造 | 建筑作品展示，secondary 0.64 是误判 |
| 排除 | 数智周报 | 新闻流水，无迁移方法 |
| 排除 | Radiant Geometries | 展览报道，只讲了颜色与几何（用户已判 0） |
