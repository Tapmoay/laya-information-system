# 信息源审计（公开版）

> 公开仓库不包含个人的来源审计历史；这里只留审计方法与判断口径。

## 什么时候审计一个源

- 连续多天 0 条；
- 抓取失败率明显高于其他源；
- 内容密度下降（标题很多、正文很少）；
- 与主方向长期不沾边。

## 判断顺序

1. **抓不到**：看 `crawl-manifest.json` 的 `reason_code`；代理/robots/付费墙分开处理；
2. **内容不好**：看列表页锚点与正文密度；这是源的问题，不是网络问题；
3. **方向不对**：看 `serves` 与当前需求；该降级就降级。

## 结论怎么写

每条审计结论要能回答：这个源是"拿不到"还是"内容不好"，
以及下一步是"换代理/改规则/降级/移除"。写不出下一步的，先别改。
