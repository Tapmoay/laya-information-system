# 39 · 判断 provider 对照：本地 decider vs 云端 API（2026-10-24）

> 问题：把每日 13 问的测量从本地 Strands Decider 2B 换到云端 `deepseek-flash`，
> **选出来的东西会不会变？** 变了多少？在换来更好的判断之前，先确认它没有悄悄换成另一套系统。
>
> 结论先说：**会变，而且变得不少。** 核心位大体保留（当天 5 条核心全部还在云端候选池，
> 排名 2/8/11/12/15），候选池重合 18/30，探索位和尾部明显换人。
> 这不是"云端更差"，是两种判断尺度不同；在没有人工标注之前，只能说不同，不能说更好。

---

## 1. 方法

- 数据：`runs/live-2026-10-24/` 当天的 225 条抓取结果，223 条可测（2 条 Check Point 空壳显式不可判）。
- A（基线）：`runs/live-2026-10-24/scores.jsonl`，本地 Strands Decider 2B，CUDA，全量。
- B（候选）：`runs/cloud-full/scores.jsonl`，`deepseek-flash`，`temperature=0`、关思考、8 并发、全量。
- 同一需求快照 `demand/demand-2026-01-01.json`、同一套 13 问、同一套权重与阈值（参数 v0001：
  0.28/0.29/0.36/0.07，阈值 0.45）。
- 合成分：`judgment/scoring.py:summarise`，与每日链路完全同一条路径。
- 排序指标：Spearman 秩相关、top-K 重合、候选池重合（`agent_select.py --build` 的真实产物）。
- 复现：

```powershell
python tools/score_items.py --provider cloud --workers 8 `
  --items runs/live-2026-10-24/items.json --demand demand/demand-2026-01-01.json `
  --profile-id cloud-full --out runs/cloud-full/scores.jsonl

python tools/compare_judges.py --scores-a runs/live-2026-10-24/scores.jsonl `
  --scores-b runs/cloud-full/scores.jsonl --items runs/live-2026-10-24/items.json `
  --label-a local --label-b cloud --out runs/cloud-full/compare.md

python tools/agent_select.py --build --scores runs/cloud-full/scores.jsonl `
  --items runs/live-2026-10-24/items.json --demand demand/demand-2026-01-01.json `
  --out runs/compare-pool/cloud --limit 30
```

## 2. 逐问句：两套尺子差在哪

| 问句 | 本地均值 | 云端均值 | Δ(云端−本地) | 平均绝对差 | ρ |
|---|---|---|---|---|---|
| primary | 0.326 | 0.345 | +0.019 | 0.136 | 0.914 |
| secondary | 0.169 | 0.137 | −0.032 | 0.091 | 0.575 |
| exploration | 0.136 | 0.345 | **+0.209** | 0.224 | 0.209 |
| task | 0.381 | 0.236 | −0.145 | 0.178 | 0.772 |
| value_task | 0.512 | 0.185 | **−0.327** | 0.353 | 0.377 |
| value_capability | 0.426 | 0.328 | −0.098 | 0.233 | 0.368 |
| value_decision | 0.285 | 0.237 | −0.048 | 0.190 | 0.295 |
| value_exploration | 0.547 | 0.335 | −0.212 | 0.218 | 0.656 |
| value_environment | 0.396 | 0.294 | −0.101 | 0.140 | 0.765 |
| quality_testable | 0.548 | 0.542 | −0.006 | 0.226 | 0.243 |
| quality_increment | 0.675 | 0.440 | **−0.235** | 0.256 | 0.449 |
| recruit | 0.143 | 0.041 | −0.102 | 0.110 | 0.436 |

读法：

- **方向问句的一致性最好**（`primary` ρ=0.914），说明"这条跟主方向有没有关系"两个模型基本同意。
- **价值问句分歧最大**：云端对 `value_task`、`value_exploration`、`quality_increment` 明显更严格，
  对 `exploration` 明显更宽松。它像是把"直接帮上忙"和"陌生视角"分得更开，
  而本地 decider 把两者都往中间拉。
- 价值是合成分的主要来源之一，所以这不是噪声，是排序变化的来源。

## 3. 合成分与候选池

| 指标 | 结果 |
|---|---|
| 合成分均值 | 本地 0.384 / 云端 0.339 |
| 平均绝对差 | 0.158 |
| 合成分 Spearman | **0.698** |
| 形态一致率 | 75.8% |
| top-5 重合 | 20% |
| top-10 重合 | 20% |
| 候选池重合（30 条） | **18/30（60%）** |
| 参数/阈值 | v0001，0.45（两边相同） |

过线率（合成分 ≥ 阈值）：

| 阈值 | 本地 | 云端 |
|---|---|---|
| 0.30 | 65.0% | 50.2% |
| 0.35 | 63.2% | 48.4% |
| 0.40 | 62.8% | 45.3% |
| 0.45 | 56.5% | 43.0% |
| 0.50 | 48.9% | 38.1% |
| 0.55 | 39.9% | 34.5% |
| 0.60 | 27.4% | 29.1% |

云端整体偏低，但高端更高（>0.60 的比例略高）。这正是"不能直接沿用 0.45"的原因：
同一个数字在另一套分布上不是同一个门槛。若只按"过线数量不变"做分布对齐，
云端阈值要降到 0.11——这说明两套分布的**尾部**形态不同，简单平移阈值并不可靠。

### 3.5 稳定性：同一批连跑两次

`temperature=0` 不等于逐位相同。抽 5 条、同样参数连跑两次（`runs/cloud-stability/`）：

| 指标 | 结果 |
|---|---|
| 问句数（5 条 × 12 问） | 60 |
| 平均绝对差 | **0.026** |
| 最大绝对差 | **0.75** |
| 形态首选项一致 | 4/5 |

最大差出现在一条建筑奖项页：第一次 `form=MARKETING / recruit=0.10`，
第二次 `form=RECRUIT / recruit=0.85`。两者都指向"降权"，但 RECRUIT 是**硬排除**、
MARKETING 只是降权——所以一次翻面就可能改变这条能不能出现。

这说明：**日常排序大体稳定，但形态与 recruit 在边界上会翻。**
终选时不要只看信号行；边界条目要回原文看它到底是什么页面。

## 4. 对当天结果的实际影响

2026-10-24 当天终选（本地分数 + Agent 判断）的 7 条，在云端分数下的位置：

| 位置 | 条目 | 云端排名 | 在云端候选池 |
|---|---|---|---|
| core | arXiv：朴素 RAW-RAG 在长对话记忆评测上多数情况胜过复杂 Agentic Memory | 2 | 是 |
| core | Consistent but Biased: Chair Personas… | 8 | 是 |
| core | Can an Agent Debug a Web Corpus? | 11 | 是 |
| core | AgentPhishing: A Benchmark of LLM Email Agents… | 12 | 是 |
| core | Mundo: From seeing a place to simulating what happens there | 15 | 是 |
| exploration | How Art Can Deliver Justice for Refugees | 66 | 是 |
| exploration | Making Generative AI Workable at Work… | 91 | 否 |

- **核心位稳**：5/5 保留，且都在云端前 15。这说明两套尺子对"能直接用的技术内容"判断接近。
- **探索位不稳**：一条掉到 66，一条掉出候选池。云端把 `exploration` 抬高、`value_exploration` 压低，
  探索位的排序依据（`exploration × 关联度`）随之变化。
- **候选池尾部换人**：云端池里出现 Edge AI 早报、性别中立代词字形、DeepSeek 推理框架等
  本地池没有的条目；本地池里的建筑、安全、图像编辑条目被挤出。

这解释了 top-10 重合只有 20%、但核心位全部保留：**分歧集中在"边缘候选"，
不是"该不该看这几篇核心"**。

## 5. 怎么解释"不同"

三种可能的解释，现有数据无法完全区分：

1. **云端更严格**：`value_task` 均值从 0.512 掉到 0.185，可能是本地 2B decider 把"稍微相关"
   也打成了 0.5 以上；云端按"能不能直接推进当前任务"的字面意思回答。
2. **问句一次问 13 个**：本地 decider 是 typed decision（每题独立头），云端是一次生成 13 个数字，
   题与题之间可能互相锚定（例如探索分高会拉低价值分）。
3. **自报 vs logit**：本地 noul 是 logit 头，云端是模型写的数字；两者的 0.5 不是同一个 0.5。

要区分，需要：同一批 30 条，云端连跑 3 次看稳定性；再把 13 问拆成 3 批问，看分数是否变化；
最后用人工标注（或两周真实取舍）判断哪套更接近"该看"。

## 6. 决定

- **2026-10-24 起，判断 provider 由 `config/user.yaml` 决定；这台机器默认本地**（ADR-0033，
  同日稍晚推翻 ADR-0032 的"默认云端"）。理由：本地权重与 GPU 现成，用户明确要求继续走本地；
  云端保留为可切换能力，实测 223 条 41 秒 / 46 万 tokens。
- **阈值暂不改**（仍 0.45）。这次没有足够证据支持新阈值；改阈值需要连续 7 天取舍记录，
  走 `tools/learn.py`。
- **换 provider 的对照成为固定动作**：任何 provider/提示词变化，先跑 30–50 条对照，
  报告落 `runs/compare/`，结论写进本文件或新的 docs/39。
- **探索位的敏感性单独跟踪**：两周复盘时对比"探索位"与"人工觉得该看的探索内容"，
  再决定要不要把 `exploration` 权重或门限改回来。

### 三个上线选项（按风险从低到高）

| 选项 | 做法 | 代价 |
|---|---|---|
| 影子运行 | 两个 provider 都落盘，终选仍用当前 provider，连续 2–3 天看候选池重合 | 每天多 41 秒 |
| 直接切换、阈值不变 | 接受候选池与探索位变化 | 需要两周复盘确认 |
| 切换并重标阈值 | 需要 30 条人工标签或 7 天取舍 | 成本最高，证据最足 |

本次交付选的是**第二项之外的最小动作**：保留本地为默认、云端作为可切换能力，
并把换 provider 前的对照门写进技能。要用云端，跑完 §1 的对照后再改配置。

## 7. 局限

1. 没有人工标注：不能回答"谁更准"，只能回答"是否相同"。
2. 稳定性只测了 5 条 × 2 次（§3.5）；其余结论来自单次运行，运行间波动未被完全刻画。
3. 小样本核心结论：7 条终选里 5 条核心的排名来自同一天，不能外推到所有日子。
4. 合成分沿用当前权重；权重本身是先验，换权重会改变重合率。
5. 形态权重是自报并归一化的，不是 softmax；形态一致率 75.8% 只能当参考。

## 8. 未做的验证与下一步

**为什么没有把 13 问拆开算**：拆开会增加调用次数与成本，而且当前一次问完的分数已经能通过契约校验。
但上面的解释 2 是一个真实假设：如果拆开后 `value_task` 显著上升，说明题间锚定存在，
届时应改成「价值 5 问一批 + 方向 4 问一批 + 形态/招募一批」，用同一份对照方法验证。

### 下一步（按优先级）

1. **形态硬排除的二次确认**：`RECRUIT` / `EVENT` 会直接硬排除，但 §3.5 显示它会翻面。
   可选做法：要求 `form=RECRUIT` 与 `recruit ≥ 0.5` 同时成立才硬排除，否则只降权；
   或对这两个形态单独再问一次。两种都要用同一批 30 条验证，不凭直觉改。
2. **人工标注 30 条**：至少能回答"云端更严格是对的还是漏的"。
3. **拆问句对照**：验证题间锚定假设。
4. **两周复盘**：用真实取舍看探索位是否变差。
