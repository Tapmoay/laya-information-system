# 33 · 测试：从单元到极端输入

> 这一轮不是加功能，是**试着把系统弄坏**。下面记的是试过什么、弄坏了什么、修了什么。

## 1. 分层

| 层 | 覆盖什么 | 命令 |
|---|---|---|
| 单元 | 每个模块的正常路径 | `python -m pytest -q` |
| 边界 | 空输入、变态文本、时间边界、坏数据、规模 | `tests/test_edge_cases.py` |
| 端到端 | 真实抓取 → 打分 → 终选 → 交付 | `tools/crawl.py` 到 `tools/final_digest.py` |
| 命令行 | 缺文件、非数组、坏 JSON | 手工探针（见第 5 节） |

## 2. 极端输入都试了什么

**空与缺字段**：空列表、没有 title、没有 text、没有 item_id、空分数、空事实集、
只有 id 的条目。

**变态文本**：两万字标题、emoji + 控制字符 + 零宽字符、纯空白、
全角半角混写、阿拉伯语 + 希伯来语 + 日语混排。

**时间边界**：没有时区的日志时间、未来的投递时间（时钟回拨）、
正好第 7 天、坏时间字符串、1999 年的发布时间。

**坏数据**：坏 JSON 行、缺 item 的候补行、超容量（120 条进 80 容量）、
全同品类的候选池、同分同名条目。

**规模**：150 条聚簇的确定性与耗时、1000 条过重复闸的耗时、
50 条含重复事件与空字段的合成批次走完聚簇 + 选择。

## 3. 弄坏了什么

**① 全角型号认不出**

`ＤｅｅｐＳｅｅｋ 发布 Ｖ４．１` 和 `DeepSeek 发布 V4.1` 被判成两件事。
原因：锚点抽取前没做 NFKC 归一，全角字符根本不进正则。
中文站点全角写法很常见，这一条会漏掉大量中文重复。
**已修**：anchors() 入口统一归一。

**② 并列排序不确定**

两条同分同名的条目，`rank()` 的顺序由输入顺序决定——同一批数据换个顺序就换个结果。
**已修**：排序键最后加上 item_id。

**③ 缺 item_id 直接崩**

一条没有 id 的坏数据会让整批聚类抛 KeyError，命令行直接 traceback。
**已修**：聚簇跳过该条、命令行提示"已跳过 N 条"。

## 4. 性能实测

| 场景 | 耗时 |
|---|---|
| 150 条聚簇 | < 1 秒 |
| 200 条嵌入编码（CPU） | 5.6 秒 |
| 1000 条过重复闸 + 聚簇 | 1.4 秒 |
| 48 条跑 13 问测量（GPU） | 约 3 分钟 |

规模上没有任何一处需要索引结构——暴力的两两比较在这个量级比建索引更快。

## 5. 命令行坏输入

| 输入 | 结果 |
|---|---|
| 文件不存在 | `错误：找不到 …`，退出码 2 |
| items.json 不是数组 | `错误：… 不是条目数组`，退出码 2 |
| 缺 item_id | 警告并跳过，退出码 0 |
| 空 items | 放行 0 条，退出码 0 |
| 空台账 | 正常工作 |

## 6. 还没覆盖的

1. **并发**：所有工具都是单进程，没有锁；两个进程同时写台账会互相覆盖。
2. **真实故障注入**：没有模拟"下载到一半断网""磁盘满""模型加载失败"。
3. **长时间运行**：没有跑过 30 天连续调度，不知道台账会涨到多大。
4. **跨语言合并的真实样本**：单测是构造的，真实中英同事件还没遇到过。
