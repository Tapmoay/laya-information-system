# 32 · 候补池：这次没选上的，明天还有一次机会

> 这份文件解决一个漏检问题：**抓取只看列表页第一屏**。
> 一条今天上了列表、今天没被选中的内容，明天就不在列表上了——它再也不会被看见。

## 1. 问题

抓取是"每次重新抓列表页"，不是"跟踪某个条目"。所以：

```text
第 1 天：A B C D E 上列表 → 打分 → 选中 A B → C D E 落选
第 2 天：列表已经换成 F G H I J → C D E 永远消失
```

C 可能比 F 更值得看，但它连被比较的机会都没有。

这不是"重要信息被筛掉"，是"重要信息根本没机会再被考虑"。

## 2. 规则

| # | 规则 | 理由 |
|---|---|---|
| 1 | 只有**过了分数门槛但没被选中**的才进候补 | 连门槛都没到的，是判断它不值得，不是没轮到它；反复回来只会占位置 |
| 2 | 候补寿命 **7 天** | 放太久的东西，时效性本身就不成立了 |
| 3 | 候补条目**保留上次的测量结果**，第二天不重跑模型 | 内容没变，重跑只是烧 GPU；时效由发布时间自动算，会自己变旧 |
| 4 | 上限 **80 条**，超出按上次分数留高的 | 防止候补无限膨胀成一个第二候选库 |
| 5 | 被选中的立即从候补移除 | 给过的东西不该再作为"没给过"回来 |

第 3 条和第 5 条是关键：前者让候补几乎零成本，后者避免和已推送台账打架。

## 3. 和台账的分工

| 机制 | 管什么 | 防的是 |
|---|---|---|
| 已推送台账（store/delivered.jsonl） | 已经给过你的 | 重复推送 |
| 候补池（store/backlog.jsonl） | 差一点给上的 | 漏掉 |

两个方向刚好相反，所以不能合并成一个文件——一个要"见过就不再提"，一个要"没给过就再提一次"。

## 4. 用法

```powershell
# 收：把这次过线但没选中的放进候补
python tools/backlog.py --carry --items runs/crawl-<日期> --scores <打分行> \
    --selection runs/agent/<日期>/selection.json --ledger store/backlog.jsonl

# 并：下一次运行前，把候补和今天的新候选合到一起
python tools/backlog.py --merge --items runs/crawl-<日期> --scores <打分行> \
    --ledger store/backlog.jsonl --out-items runs/merged/items.json --out-scores runs/merged/scores.jsonl
```

合并后的 items/scores 直接喂给 `tools/agent_select.py --build` 就行，
候补条目会带 `from_backlog` 与 `backlog_attempts` 两个字段，终选时能看出来它是第几次来。

## 5. 实测

第一次实跑（120 条抓取、48 条打分、选 7 条）之后收候补：

```
候补：新增 20 条，合计 20 条 → store/backlog.jsonl
```

20 条 = 打分过 0.40 线但没被选中的全部（8 条是我明确排除的，其余是没进前 15 的）。
合并回今天的数据时不重复（同 id 以今天为准），说明去重和"回来再试"不打架。

## 6. 还没做的

1. **候补没有"最后期限提醒"**。一条内容在候补里躺了 5 天、明天就过期，
   系统不会告诉任何人。要不要提示，取决于你觉得吵不吵。
2. **候补的排序只按上次分数**。如果它第二天被另一条更好的内容挤掉，
   第三次还是按原分数排——没有"连续 N 次落选就降级"的机制。
3. ~~跨语言候补~~ **已解决**（见下一节）。

## 6.5 跨语言合并（已解决）

原来的漏洞：两天前用英文进过候补，今天来的是中文那条——**item_id 不同，认不出来**，
于是同一件事会占两个候选位，或者英文那条被当成新东西又回来一次。

现在 merge 支持一个 `same_event` 回调，默认接跨语言向量判定（余弦 ≥ 0.90）：

| 情形 | 处理 |
|---|---|
| 同 item_id | 以今天为准（原有行为） |
| 不同 id、不同语言、判定为同一事件 | **只留今天那条**，候补条目并入 |
| 判定不是同一事件 | 照常复活，两条都进池 |

并入时保留痕迹：今天那条会带上 `backlog_merged_from`（被并入的 id）、
`backlog_attempts`（等待次数累加）与 `backlog_merge_similarity`（当时的余弦）。
这样"它其实等了两天"这件事不会在合并时丢掉。

为什么留今天那条而不是候补那条：今天的更新，而且是中文——用户读中文。

用法加一个 `--embed`：

`@powershell
python tools/backlog.py --merge --items runs/crawl-<日期> --scores <打分行> ^
    --ledger store/backlog.jsonl --embed --out-items runs/merged/items.json
`@

没有装本地多语言模型时会明确打印"跳过跨语言合并"，不会静默降级。
