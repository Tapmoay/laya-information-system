# 34 · 按外部建议改的三件事：通道、状态、复盘

> 收到一份外部建议，核心是：真正的难题不是"去哪找好信息"，而是
> **在还不知道自己要什么的情况下，建立一套不淹没、也不把机会挡在外面的系统**。
> 这份文件记录：哪些我们已经做了、哪些补上了、哪些明确不改。

## 1. 建议里我们已经做了的

| 建议 | 我们的对应 | 状态 |
|---|---|---|
| 价值四分法（决策/能力/探索/审美） | 13 问里的五项政策价值（任务/能力/决策/探索/环境），审美落在次方向 | 已有，且比它多一项"环境价值" |
| 不因热门、自信、新奇就加分 | 政策 §2.2 + 产品公告降权 | 已有 |
| 不要为了完整而保存一切 | "密度低一律不要" + 每条都要过分数门槛 | 已有 |
| 承认会漏，目标不是零遗漏 | 写进 docs/29、docs/32 | 已有 |
| 用真实结果回头修规则 | 反馈 → 参数 → 校准 | 已有（但缺"两周"这个节奏） |

所以这份建议里真正新的，是三件结构性的东西。

## 2. 补上的第一件：三条通道

**原来**：一条 5+2 的流，核心位和探索位只是两个槽位。

**现在**：按**工作方式**分三条通道，判据不同：

| 通道 | 要解决什么 | 判据偏重 |
|---|---|---|
| A 目标驱动 | 把正在做的事推进下去 | 任务价值、主方向 |
| B 变化监测 | 别漏掉会影响未来判断的外部变化 | 环境价值（**现在用不上也留**） |
| C 受控探索 | 扩大"我不知道自己需要什么"的接触面 | 探索价值、审美与表达（次方向） |

分配是确定性的（`judgment/channels.py`）：三个通道各算一个分，取最大；
平手时 A > B > C（能用优先）。

为什么必须分开：同一把尺子量，B 和 C 一定被 A 挤掉——不是它们不重要，
是它们不"急"。这次实跑的结果正好说明：7 条里 A 5 / B 1 / C 1，
如果没有通道，那个 B 和 C 根本进不来。

### 2.1 C 通道不按形态排除，只打标记

用户 2026-10-20：「跨领域探索的话，不要卡得太死」。

实测过两次一刀切的代价：
- 按 `form=MARKETING` 排除，建筑与设计作品也被模型标成 MARKETING，C 从 18 条掉到 4 条；
- 按"商业词 ≥3"排除，麦当劳那篇讲画面怎么搭的也被误杀。

所以改成**标记而不是剔除**：商业内容照进 C，结果里带 `commercial: true`，
产物上标一句"（商业内容，仅标记）"。剔不剔除由人决定，不由一个词表决定。

这条与主旨第 3 条一致：**好内容 ≠ 对你有用的内容**，反过来也成立——
"看起来像广告"不等于"没有可用的东西"。特斯拉那篇讲的是风扇吸附与 2g 横向加速度，
它本身是一篇技术分析，只是发生在一次营销事件上。

## 3. 补上的第二件：三种处理状态

**原来**：选中 / 排除，两态。

**现在**：值得深入 / **值得暂存** / 直接放弃。

| 状态 | 判据 | 怎么处理 |
|---|---|---|
| 值得深入 | 分数 ≥ 0.60 | 进主交付，有摘要与理由 |
| 值得暂存 | 0.40 ≤ 分数 < 0.60 | **只留链接 + 一句为什么**，不展开 |
| 直接放弃 | < 0.40 | 消失，不留痕迹 |

"值得暂存"这一节直接复用候补池（`store/backlog.jsonl`）——那本来就是
"过线但没排上"的条目，7 天内还会再参与一次挑选。所以这一节不需要新的存储，
只需要一个渲染。

建议里那句"不是所有有价值的信息都值得保存，值得保存的也不一定值得立即阅读"，
落到实现上就是：**暂存只写一行**，不生成摘要、不抓正文。

## 4. 补上的第三件：两周复盘

新增 `tools/review_cycle.py`：把最近 14 天真推出去的条目导成一张表，三栏勾选：

- 帮到了（改变了判断 / 推进了任务 / 建立了能力）
- 一时兴趣（当时觉得有意思，事后没有用）
- 不该推

外加一栏是系统看不见的：**我本来该看到、但它没给我的**。

这一栏才是关键——自动系统只能复盘"我给了什么"，复盘不了"我漏了什么"。
那部分只能靠人写下来，再回灌给规则。

## 5. 明确不改的两处

**① 不把抖音/B站/YouTube 接成主要来源。**

建议里说"不建议彻底放弃，但要把它们从主要供应者变成受你控制的发现渠道"——
后半句我完全同意，前半句我做不到而且不该做：

- 抓取层不做 JS 渲染（这是"同一份 HTML 永远得到同一组链接"的前提），
  这三个平台恰好全是 JS 渲染；
- 更重要的是，它们的信息密度按政策 §2 是**低**的，接成常规来源会直接违背
  "密度低一律不要"。

正确的做法是**受控发现**：你在上面看到什么，把链接扔给系统，系统判它值不值得占位。
这一步还没做（下一步：evaluate_link（尚未实现））。

**② 不设"零遗漏"目标。**

已经写在 docs/29（漏检与误并的取舍）和 docs/32（候补池的寿命上限）。
候补只保留 7 天、80 条，就是为了承认"有些东西会掉出去，这是设计的一部分"。

## 6. 与"未知需求"的关系

C 通道就是未知需求的入口。但它的判据**不能只是"陌生"**——
那会退化成"越奇怪越优先"。我们的做法是：陌生 + 能连回主/次方向（关联度），
关联度越高优先级越高。这条写在 AGENT.md §4.2③。

换句话说：探索不是"什么都看"，是"在能连回来的方向上往外走一步"。

## 7. 输出形状变了

```text
原来：核心 5 + 探索 2
现在：通道 A（目标驱动）
      通道 B（变化监测）
      通道 C（受控探索）
      值得暂存（只留链接）
```

7 条的总量没变，但**分组方式变了**：你能看出来每一条是"用来做事的"、
"用来防止漏掉变化的"，还是"用来扩大接触面的"。

## 7.5 受控发现：把链接扔进来

建议里说"不建议彻底放弃抖音/B站/YouTube，但要把它们从主要供应者变成受你控制的发现渠道"。
前半句不做（JS 渲染 + 密度低），后半句已经落地：

@@@powershell
python tools/evaluate_link.py https://example.com/some-article
@@@

它做三件事：抓这一页 → 跑同一套 13 问 → 告诉你**哪条通道、哪个状态、为什么**。

实测（arXiv 一篇文章）：

@@@
标题：FDE-Gym: The Last Mile of AI Delivery
分数：0.699　状态：值得深入　通道：A（目标驱动）
通道分：A 0.81 / B 0.46 / C 0.09
时间：18.23 天前（ARXIV_ID，MONTH）
@@@

**关键的一条设计**：抓不到可读正文时，它会直接说"拿不到"，**不拿空壳去打分**。
实测 YouTube 页面返回 105 字，工具退出码 3：

@@@
拿不到可读正文（105 字）。这类页面多半靠 JS 渲染，换个能直接读的地址，
或者把标题和要点贴给我。
@@@

这比"硬着头皮打一个分"诚实得多——空壳打出来的分只会污染判断。

## 8. 下一步

1. **主动检索**：已知需求里除了"等推"，还应该有"我去找"。现在没有搜索能力，
   只有固定源抓取——这是与建议最大的差距。
2. **审美与表达没有独立的价值维度**：它现在落在次方向 + C 通道里，
   13 问里没有一问专门问"它有没有扩展我的表达工具"。
3. 两周复盘写回来的"漏掉了什么"，还没有路径变成规则（现在只能人工改文档）。
